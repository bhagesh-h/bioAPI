Sequence analysis toolkit · REST API

Sequence analysis
as a web service.

bioAPI does the routine jobs that come up whenever you handle sequence data — summarising a file, cleaning it up, filtering out poor-quality reads, converting between formats. You hand it a file, it hands back the result. There is no software to install on your own machine and no script to write.

Capabilities Getting started All 44 endpoints

DNA has two strands that mirror each other, and reading the second one is something you end up doing constantly. Give bioAPI the strand you have and it returns the other one. Every other operation works the same way: send what you have, get back what you wanted.

Audience

Intended users

This documentation assumes no prior knowledge of either the biology or the web-service conventions. Both are covered below.

Laboratory and research users

No programming required

You do not have to write code to use this. Once it is running, it comes with a web page where you pick an operation, upload your file, press a button and read the answer — the same way you would use any online tool, except it runs on your own machine and your files never leave it. The computing words are explained below.

Software developers

A conventional REST interface

It is an ordinary REST API: JSON in, JSON in one consistent envelope out, an OpenAPI document, health probes and Prometheus metrics. What needs explaining is what a FASTQ file is and why anyone wants its N50 — also below. The full route list is in the API reference.

Capabilities

Operation categories

Forty-four operations in total. They fall into six groups, described here in ordinary words; the exact names, inputs and outputs are in the API reference.

Single-sequence operations

11 operations

Paste in one stretch of DNA, RNA or protein and get something back about it, or a transformed version of it.

Read the opposite strand · turn DNA into RNA · translate it into the protein it codes for · measure how much of it is G and C · find every position where a short pattern occurs · count repeated chunks · check whether it is valid at all.

FASTA file manipulation

14 operations

Take a FASTA file — a text file holding many named sequences — and reshape it. This is the group people use most, because real files are never quite in the shape you need.

Summarise what is in it · keep only sequences within a length range · take the first N or a random sample · split one file into several or merge several into one · shorten over-long names · rename entries · strip out unexpected characters · remove duplicates · list the names.

FASTQ and read quality

5 operations

A sequencing machine outputs FASTQ: the same sequences, but each base carries a score saying how confident the machine was. These operations use those scores.

Report the average quality and what fraction of bases clear the usual Q20 and Q30 bars · throw away reads that fall below a threshold · drop the scores to get a plain FASTA · compress and decompress.

File inspection and format detection

4 operations

Upload any sequence file and find out what it actually is and what is inside it. It works out the format by reading the contents, not by trusting the filename — so a FASTA file someone saved as .txt is still recognised.

Identify the format and summarise it · pull out the gene sequences listed in an annotation file · list the variants of a given kind in a VCF.

Format conversion

2 operations

The same sequences get stored in a handful of different text formats, and the tool you want to use next rarely reads the one you have.

Convert between FASTA, GenBank, EMBL, tab-separated and JSON · apply a list of variants to a reference genome to produce that sample's own version of the sequence.

Service capabilities and health

1 operation, plus 7 status checks

One address reports which conversions are possible and, for the ones that are not, why not — so a program using bioAPI can ask rather than guess. Alongside it are the addresses that report whether the service is alive and which versions it is running.

Glossary

Terminology

Every term used on this site and in the reference, in one place. The left column is the biology, the right column is the computing.

FASTA
A plain text file holding one or more sequences. Each entry starts with a name line beginning >, followed by the letters of the sequence.
API
A way for one program to ask another to do something, without a person clicking through a screen. bioAPI is the second program.
FASTQ
What a sequencing machine produces. Like FASTA, but every base also carries a score saying how sure the machine was about it.
Endpoint
One web address that does one specific job. /api/v1/fasta/stats summarises a FASTA file and does nothing else.
GenBank and EMBL
Richer text formats that carry annotations — where the genes are, what they are called — alongside the sequence itself.
Request and response
You send a request (your file and your options); the service sends back a response (the answer). The same exchange your browser makes to load a page.
VCF
A list of the positions where one sample differs from a reference genome, and what it has instead.
JSON
A plain text way of writing structured data that programs can read reliably. Every answer bioAPI gives comes back in it.
GFF and GTF
A list of features — genes, exons — and the start and end positions they occupy along a sequence.
Status code
A number in the response saying how it went. 200 means fine, 400 means your input was rejected, 500 means the fault was ours.
Reverse complement
DNA's two strands mirror each other — A pairs with T, G with C. Given one strand, the reverse complement is the other one, read in the direction it is normally written.
Docker and containers
A sealed box holding the software and everything it depends on, so it behaves the same on any machine. It is how bioAPI is run.
GC content
The percentage of a sequence made up of G and C. It varies between organisms and between regions, and it affects how a sequence behaves in the lab.
curl
A small command-line program that sends a request and prints the response. It is what the examples use, but any language can do the same.
N50
A way of saying how long the pieces in an assembly are: half of all the sequence sits in pieces at least this long. Higher usually means a better assembly.
API key
An optional password sent with each request. bioAPI is open until you set one; after that, requests without it are refused.
Quality score, Q20, Q30
How confident the sequencer is about a base. Q20 means about one wrong call in a hundred, Q30 about one in a thousand.
Rate limit
A cap on how many requests one user can send in a given period, so that nobody can overwhelm the service. The default is 120 a minute.
Translation
Turning DNA or RNA into the protein it codes for, three letters at a time. Which triplet means which amino acid depends on the organism, so the code can be chosen.
Warning
A note attached to a successful answer — twelve records were skipped, a partial triplet was dropped. The operation worked; something is still worth knowing.

Getting started

Installation and first request

Everything runs on your own machine, so your files stay on it. The only thing you need installed first is Docker, which is a free download.

STEP 1

Start the service

Paste these three lines into a terminal. The first download takes a few minutes; after that it starts in seconds. 

git clone https://github.com/bhagesh-h/bioAPI.git
cd bioAPI
docker compose up api
STEP 2

Interactive browser interface

Open this address in your browser. You get a page listing every operation: pick one, fill in the boxes or upload a file, press Execute, read the answer.

This is usually the right starting point if you are not a programmer.

http://127.0.0.1:8000/docs
STEP 3

Programmatic access

Every operation is also a plain web request, so any language can drive it. This one asks for the opposite strand of a short sequence. 

curl -X POST http://127.0.0.1:8000/api/v1/sequences/reverse-complement \
  -H 'Content-Type: application/json' \
  -d '{"sequence":"ATGCGTAA"}'

Roadmap

Known gaps and candidate features

Worth being straight about the gaps. These are candidates drawn from comparing bioAPI against SeqKit, the closest command-line equivalent, and against what Biopython and pysam can already do inside the container. None of it is built. The full write-up, with draft routes, is in docs/roadmap.md.

Primer and protein analysis

No new dependencies

The biggest hole. bioAPI ships Biopython but only uses a corner of it, so these are a service function and a route away rather than a new dependency.

Melting temperature for a primer · molecular weight · isoelectric point and the other protein properties · open reading frames across all six frames · restriction cut sites · codon usage · pairwise alignment.

File-level operations

Currently single-sequence only

Several operations exist for one pasted sequence but not for a file full of them, which is usually the case you actually have.

Find a motif across every record · translate a whole FASTA file · sort by length or name · cut into sliding windows · rename with a pattern instead of a hand-written map · records common to several files.

Sequencing workflow support

Highest-priority gap

Reads arrive as a pair of files and usually arrive compressed. Every operation today treats a file as standalone and uncompressed.

Paired-end R1/R2 handling, so filtering keeps mates together · converting quality encodings between Sanger, Solexa and Illumina · accepting a gzipped upload anywhere, not only on the two FASTQ endpoints · reading BED regions alongside GFF.

Large input handling

Currently capped at 50 MB

Everything is synchronous: you wait on the request until the answer comes back. That does not survive genome-scale files or an impatient proxy.

A submit-and-poll job model, as EMBL-EBI's Job Dispatcher uses · batching many sequences into one call · streaming a conversion as it is produced · paging through per-record results.
