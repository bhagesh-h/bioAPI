rest api · fastapi · biopython · pysam

Sequence work, over HTTP.

Reverse-complement a read, compute N50, filter a FASTQ by mean quality, convert GenBank to FASTA, or apply a VCF to a reference — as HTTP calls, with one response shape for every endpoint. Runs in a container; there is nothing to install.

quick start

Docker is the only supported toolchain

pysam's C extensions build once, inside an image where they are known to work, rather than on each contributor's laptop. There is no host virtualenv and no pip install.

run it

# the API comes up on 127.0.0.1:8000
git clone https://github.com/bhagesh-h/bioAPI.git
cd bioAPI
docker compose up api

# interactive docs, generated from the code
open http://127.0.0.1:8000/docs

call it

curl -X POST http://127.0.0.1:8000/api/v1/\
sequences/reverse-complement \
  -H 'Content-Type: application/json' \
  -d '{"sequence":"ATGCGTAA","alphabet":"dna"}'

what comes back

{
  "success": true,
  "message": null,
  "data": { "result": "TTACGCAT", "length": 8 },
  "error": null,
  "warnings": [],
  "request_id": "c20b1ca5-9c54-4297-8040-a944c809bc5b"
}

everyday commands

make up       # serve on port 8000
make test     # suite behind a 90% coverage gate
make lint     # ruff + mypy --strict
make smoke    # start, probe /health/ready, tear down
make shell    # a shell in the dev image

what it does

Six things worth knowing

One envelope, everywhere

Every JSON endpoint returns the same six fields, so a client writes one unwrapping helper and reuses it for all 37 versioned routes.

Detection reads content, not extensions

A FASTA file named sample.txt is still reported as FASTA, with a confidence level and the reason behind the verdict.

Warnings you should actually read

An operation can succeed and still have something to tell you: 12 records skipped, a VCF variant that did not match the reference, a partial codon dropped.

The API describes itself

GET /api/v1/formats publishes the conversion matrix and the reason each unavailable pair is unavailable, so clients need not hard-code it.

Impossible work is refused up front

Converting to FASTQ from a source without quality scores fails immediately with an explanation, rather than deep inside Biopython after the upload is read.

Safe defaults before you configure anything

Optional API key, per-key rate limiting, upload caps enforced twice, security headers on every response, and an unprivileged container user.

Sequences

/api/v1/sequences 11

All eleven share a JSON body: sequence, optional alphabet (dna, rna, protein, or omitted to auto-detect), uppercase and remove_whitespace. Whitespace is stripped before processing, so a wrapped sequence pastes in fine. IUPAC ambiguity codes are valid but produce a warning, because most calculations treat the code literally rather than expanding it. Nucleotide-only operations reject a sequence declared as protein.

FASTQ utilities

/api/v1/fastq 5

Every request carries fastq_string and quality_offset (33 for Sanger and Illumina 1.8+, 64 for older Illumina). Parsing is strict: exactly four lines per read, @ first, + third, sequence and quality of equal non-zero length. Errors name the read number. Line-wrapped FASTQ cannot be parsed unambiguously and is rejected rather than guessed at.

EndpointWhat it doesExtra fields

POST/quality-filterKeep reads above a mean Phred score and a minimum length.min_quality (default 20), min_length
POST/to-fastaDrop the quality track.line_width

Conversions

/api/v1/conversions 2

Both return a file directly, with the metadata in X- response headers rather than a JSON body.

EndpointWhat it doesParameters
POST/convertConvert between formats. The pair is checked before the upload is read, so an unsupported one costs no I/O and comes back with the list of targets that would work. GenBank and EMBL need a molecule_type; when the source lacks one it is inferred and reported as a warning. Converting from FASTQ drops the quality scores, also as a warning.query source_format, target_format; multipart file
POST/vcf-to-fastaApply a VCF to a reference to build a consensus. The first ALT of each record is used, applied from the end of each sequence backwards so an indel cannot shift the coordinates of the variants still pending. A variant is skipped when its chromosome is absent, its position is out of range, or its REF does not match the reference — usually a different reference build. References with no variants pass through unchanged, so the record count always matches the input.reference_fasta, vcf_file

Authentication and rate limiting

An unset API_KEY leaves the API open. Once it is set, every /api/v1 route needs the X-API-Key header — missing is a 401, wrong is a 403, compared in constant time. The scheme is declared in the OpenAPI document, so Swagger UI renders an Authorize button rather than a stray header field on every operation.

Rate limiting is a fixed window keyed on the API key when present, otherwise on X-Forwarded-For or the peer address. The counter is per process: behind several replicas each enforces its own share, so put a global limit on the ingress if you need one. Exempt: /health, /health/live, /health/ready, /ready, /metrics.

Worked examples

analyse a file

curl -X POST http://127.0.0.1:8000/api/v1/files/stats \
  -F "file=@reads.fastq"

convert fasta to genbank

curl -X POST "http://127.0.0.1:8000/api/v1/conversions\
/convert?source_format=fasta&target_format=genbank" \
  -F "file=@genome.fasta" -o genome.gb

build a consensus from a vcf

curl -X POST http://127.0.0.1:8000/api/v1/conversions\
/vcf-to-fasta \
  -F "reference_fasta=@ref.fasta" \
  -F "vcf_file=@variants.vcf" -o consensus.fasta

reproducible sampling

curl -X POST http://127.0.0.1:8000/api/v1/fasta\
/sample-sequences \
  -H 'Content-Type: application/json' \
  -d '{"fasta_string":">a\nACGT\n>b\nTTGG","n":1,"seed":42}'
